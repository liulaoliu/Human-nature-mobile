### P1-1 仿写页的「必须用上的词块」输入框吞掉分隔符，用户打不出第二个词块

- **Symptom**：在仿写页的词块输入框里敲 `run、up`，框里只剩 `runup`；敲 `run, up` 同样被吞。想加第二个词块只能靠粘贴。
- **Source**：`lib/views/writing_panel.dart:41-46`

  ```dart
  void _sync(WritingViewModel vm) {
    if (_model.text != vm.model) _model.text = vm.model;
    if (_text.text != vm.text) _text.text = vm.text;
    final joined = vm.mustUse.join('、');
    if (_mustUse.text != joined) _mustUse.text = joined;  // ← 覆盖用户正在敲的原文
  }
  ```

  `build` 里 :87 每次都调 `_sync(vm)`；输入框 :105-113 的 `onChanged: (String raw) => vm.setMustUse(_parseMustUse(raw))`。
- **机制**：用户敲到 `'run、'` → `_parseMustUse`（:48-52，`split(RegExp(r'[、,，;；\n]'))` + 去空）得到 `['run']` → `setMustUse` 触发 `notifyListeners` → 重建 → `_sync` 用 `join('、')` 算出 `'run'`，与框里 `'run、'` 不等，于是把框改回 `'run'`。**分隔符永远存不住。**
- **探针实测**（`test/views/probe_must_use_test.dart`，已删）：逐键输入 `r/u/n/、/u/p`，框内依次为 `r` / `ru` / `run` / `run`（顿号被吞）/ `runu` / `runup`；`Expected: 'run、up'` / `Actual: 'runup'`。
- **附带**：`TextEditingController.text = x` 之后 `selection` 变成 `TextSelection.invalid`（另一探针确认），用户继续输入会插到末尾 —— 光标也会跳。
- **Consequence**：`mustUse`（提示词里「必须用上的词块」那段）实际上只能靠粘贴或单条输入，仿写训练的核心练法之一半残。
- **Remedy**：不要用「解析后的值」反写输入框。改成只在该字段被**外部**改动时同步（例如记住上一次自己写进去的 `joined`，或给 VM 加一个 `mustUseDirty` 计数器）；或者干脆让输入框不受控、只做单向 `onChanged`（`TextField` 初始值从 VM 取一次，之后不再回写）。参考同项目的 `lib/views/production_run.dart:87-90` 与 `lib/views/drill_sentence_page.dart:76-82` —— 那里同步的是「作答原文」这种**不经解析**的字符串，所以不踩；`drill` 版还显式设了 selection。
